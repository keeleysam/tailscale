# Tailscale tvOS AppConfig policy template

This is the tvOS sibling of [`docs/ios/policy/`](../../ios/policy/README.md): same [AppConfig](https://www.appconfig.org/ios.html) mechanism, same generator (`cmd/genpolicydocs`), same workflow for turning this spec into a deployable plist via the [AppConfig Generator](https://generator.appconfig.jamfresearch.com/generator). Read that README first for the shared background (what AppConfig is, how to generate a plist and test it with Jamf, the "Not configured" defaults pattern, the array-field caveat); this file only covers what's different about tvOS.

## Same bundle ID as iOS, different key set

Tailscale's tvOS app uses the exact same main bundle identifier as its iOS app, `io.tailscale.ipn.ios` (only the network extension has a distinct tvOS-specific bundle ID). Despite sharing a bundle ID, this is a **separate file**, not the same one reused, because tvOS supports a different subset of policies than iOS: some keys appear only in the iOS file (e.g. `ExitNodesPicker`, the exit node picker UI, which doesn't apply to tvOS's remote-control-driven interface, though the underlying key also covers macOS/Windows/Android), and some appear only in the tvOS file (e.g. `RunExitNode`, the UI toggle for showing/hiding the "run as exit node" menu item, not to be confused with the actual run-as-exit-node capability itself, `AdvertiseExitNode`, which is a separate key left universal and does apply to iOS). `DeviceSerialNumber` is supported on both, since both are sandboxed mobile platforms that can't read their own serial number.

## Platform data is generated the same way, just less complete

`util/syspolicy/policy_keys.go` is the source of truth for which keys apply to tvOS, same as for iOS. As of this writing, accurate tvOS/iOS differentiation has only been filled in for the `VisibilityValue`-typed keys (UI show/hide toggles), sourced from the per-key platform table on https://tailscale.com/kb/1315/mdm-keys. Functional/behavioral keys (the actual VPN settings, not UI toggles) are left at their default of "supported everywhere" unless `pkey.go`'s own doc comments say otherwise, even where that KB table doesn't list tvOS for them: the KB's per-key table is scoped to MDM-deployable platforms specifically and has no Linux column at all, so its omissions aren't reliable evidence for narrowing a field whose doc comment says "supported on the current OS" in the general sense. That means this file may currently include some functional keys that don't really do anything meaningful on tvOS; that's an accepted, over-inclusive starting point, not a bug.
